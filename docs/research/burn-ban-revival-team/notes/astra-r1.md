# How Sam should rebuild isthereaburnban.com

Research notes · November 23, 2026 (US Central)

## Takeaway

Use Astro to publish the fast, one-screen site on Cloudflare Workers Static Assets. Let a scheduled Worker update D1 independently and serve current county HTML and JSON from the same record.
Start with Oklahoma and Texas. Give each result an official link, a checked time and a named jurisdiction. When the source cannot answer, say so.
Offer opt-in alerts for a chosen area. The first likely paid upgrades are reliable email bursts and enough Worker CPU to process larger feeds.

## Cited findings

All access dates are November 23, 2026. Documentation and agency pages were read in part unless marked otherwise. Counts and examples from curl are observations from this run, not live status for a reader’s location.

### Hosting and refresh costs

- Astro prerenders by default. An individual route can use `prerender = false` with `@astrojs/cloudflare`. Static-only Astro needs no adapter and its components can ship as HTML/CSS without a client runtime. The Astro 6 adapter dropped Pages support and accepts a custom Worker entry point. Hono supports routing, static assets and a scheduled handler in the same module. [Astro rendering](https://docs.astro.build/en/guides/on-demand-rendering/) · [Astro islands](https://docs.astro.build/en/concepts/islands/) · [Cloudflare adapter](https://docs.astro.build/en/guides/integrations-guide/cloudflare/) · [Hono on Workers](https://hono.dev/docs/getting-started/cloudflare-workers)
- Workers Free includes 100,000 dynamic requests/day, five Cron Triggers/account, 10 ms CPU per HTTP **and scheduled** invocation, 50 subrequests/invocation, 20,000 static files/version and 25 MiB/file. Network wait is excluded from CPU. Static asset requests are free and unlimited when served directly. A worker-first route invokes the Worker even for matching assets and can return 429 after quota. Generating one static file for every Census ZCTA would already exceed the free file limit. Workers Paid starts at $5/month per account. [Workers limits](https://developers.cloudflare.com/workers/platform/limits/) · [Asset billing](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/) · [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/)
- Pages Free allows 500 builds/month and 20,000 files/site. Functions share the Workers request allowance. One daily build fits. Hourly builds would use 720 in a 30-day month. Workers Builds instead measures minutes, with 3,000/month on Free. A Workers Cron Trigger runs a `scheduled()` handler on UTC time. [Pages limits](https://developers.cloudflare.com/pages/platform/limits/) · [Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/limits-and-pricing/) · [Functions pricing](https://developers.cloudflare.com/pages/functions/pricing/) · [Cron Triggers](https://developers.cloudflare.com/workers/configuration/cron-triggers/)
- D1 Free includes 5 million rows read/day, 100,000 written/day and 5 GB total, capped at 500 MB per free database. Reads count scanned rows and indexes add writes. A D1 `batch()` rolls back all statements on failure. KV Free includes 100,000 reads and 1,000 writes/day, 1 GB stored. Other locations can see an old KV value for 60 seconds or longer. R2 Standard includes 10 GB-month, 1 million Class A and 10 million Class B operations/month, with free egress. [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/) · [D1 limits](https://developers.cloudflare.com/d1/platform/limits/) · [D1 transactions](https://developers.cloudflare.com/d1/worker-api/d1-database/) · [KV pricing](https://developers.cloudflare.com/kv/platform/pricing/) · [KV consistency](https://developers.cloudflare.com/kv/concepts/how-kv-works/) · [R2 pricing](https://developers.cloudflare.com/r2/pricing/)

### Alert delivery

- **Web push.** Cloudflare’s own example uses `web-push`, VAPID keys, an encrypted payload and a service worker that displays the notification. Its sender retires subscriptions on 404/410. Workers compatibility dates from August 4, 2026 enable supported Node APIs by default. A Web Crypto alternative, `@block65/webcrypto-web-push`, ships a Workers/D1 example and browser integration tests. In one independent October 13 test of 29 sends on Chrome and Edge for Windows, an unsubscribed endpoint continued to accept messages for minutes. Verify actual display on target devices. [Cloudflare example](https://github.com/cloudflare/agents/blob/main/docs/agents/push-notifications.md) · [Compatibility dates](https://developers.cloudflare.com/changelog/post/2026-08-04-nodejs-compat-default/) · [Web Crypto implementation](https://github.com/block65/webcrypto-web-push) · [Firsthand test](https://xndr.io/blog/web-push-cloudflare-workers)
- Browser subscriptions require HTTPS and expose an endpoint that must be kept private plus `p256dh` and `auth`. On iOS/iPadOS 16.4+, a Home Screen web app can request push after a direct user gesture. Apple developer membership is unnecessary. Provide a manifest, an install hint and an email option on the same screen. [Push subscription](https://developer.mozilla.org/en-US/docs/Web/API/PushSubscription) · [Subscribe options](https://developer.mozilla.org/en-US/docs/Web/API/PushManager/subscribe) · [WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)
- **Email.** Cloudflare Email Sending is in beta. Sending to arbitrary subscribers requires Workers Paid, a verified sending domain on Cloudflare DNS, and a reputation-dependent daily quota. The plan includes 3,000 outbound emails/month, then $0.35/1,000. Email Routing forwards inbound mail. Free sends to the account’s verified routing destinations are unsuitable for a public subscriber list. [Service](https://developers.cloudflare.com/email-service/) · [Pricing](https://developers.cloudflare.com/email-service/platform/pricing/) · [Limits](https://developers.cloudflare.com/email-service/platform/limits/) · [Domain setup](https://developers.cloudflare.com/email-service/get-started/send-emails/)
- Resend Free allows 100/day and 3,000/month. Each recipient counts, and confirmation emails consume quota. Its $20/month tier lists 50,000 emails. Postmark’s free developer plan allows 100/month, with paid plans starting at $15/month for 10,000. Postmark explicitly includes individual, opted-in alerts in its transactional examples. [Resend quotas](https://resend.com/docs/knowledge-base/resend-email-quota) · [Resend pricing](https://resend.com/pricing) · [Postmark pricing](https://postmarkapp.com/pricing) · [Postmark message classification](https://postmarkapp.com/support/article/804-what-are-transactional-emails)
- **Retries and consent.** Cloudflare Queues delivers at least once. Free includes 10,000 operations/day, usually three per successfully delivered message, and 24-hour retention. Resend accepts an idempotency key for 24 hours. US CAN-SPAM rules depend on the message’s primary purpose. For commercial mail, use accurate headers and subject, identify advertising where required, include the sender’s valid postal address and provide an opt-out honored within 10 business days. Double opt-in is a product choice. [Queues pricing](https://developers.cloudflare.com/queues/platform/pricing/) · [Delivery guarantees](https://developers.cloudflare.com/queues/reference/delivery-guarantees/) · [Retention](https://developers.cloudflare.com/queues/platform/limits/) · [Resend retries](https://resend.com/docs/dashboard/emails/idempotency-keys) · [15 USC §7704](https://www.govinfo.gov/content/pkg/USCODE-2024-title15/html/USCODE-2024-title15-chap103-sec7704.htm) · [16 CFR §316.3](https://www.govinfo.gov/content/pkg/CFR-2024-title16-vol1/xhtml/CFR-2024-title16-vol1-part316.html)

### ZIP and map

- The Census 2020 ZCTA-to-county file fetched in full, 6,821,287 bytes. Counting distinct county GEOIDs with positive overlapping land area, **10,180 of 33,791 represented ZCTAs intersected multiple counties**. Oklahoma’s 74008 includes Tulsa and Wagoner. ZCTAs approximate postal geography and omit some valid ZIPs. HUD’s USPS crosswalk is an alternative for delivery ZIPs, but the public API returned `Unauthenticated` in this run. [Census file](https://www2.census.gov/geo/docs/maps-data/data/rel2020/zcta520/tab20_zcta520_county20_natl.txt) · [Census definitions](https://www.census.gov/programs-surveys/geography/guidance/geo-areas/zctas.html) · [HUD API](https://www.huduser.gov/hudapi/public/usps)
- The `us-atlas@3.0.1` county TopoJSON fetched in full was 842,143 bytes, or 250,216 bytes locally gzipped at level 9. It uses simplified 2017 geometry and five-digit FIPS identifiers. Census discourages using cartographic boundaries for precise location relationships. This size is a reference for a browse map. For a current build, Census’s 2025 generalized county download was 907,162 bytes by HTTP HEAD. Its 2026 detailed county ZIP was 83,378,454 bytes. Build the display map offline and query detailed, versioned polygons for pins. [Measured file](https://cdn.jsdelivr.net/npm/us-atlas@3.0.1/counties-10m.json) · [Dataset notes](https://github.com/topojson/us-atlas) · [2025 browse geometry](https://www2.census.gov/geo/tiger/GENZ2025/shp/cb_2025_us_county_20m.zip) · [2026 detailed geometry](https://www2.census.gov/geo/tiger/TIGER2026/COUNTY/tl_2026_us_county.zip) · [Census guidance](https://www.census.gov/programs-surveys/acs/geography-acs/geography-tools.html)
- Leaflet advertises about 40 KB of JS and accepts GeoJSON. A tileless county outline is enough for browsing. For streets and public-land boundaries, MapLibre renders vector tiles via WebGL. OpenFreeMap offers free public tiles without keys or stated view limits, requires attribution and offers no SLA. Its Liberty style returned valid JSON with 111 layers. Protomaps supports extracting a regional PMTiles archive and serving it from R2 with a Worker tile endpoint. [Leaflet](https://leafletjs.com/) · [MapLibre](https://maplibre.org/maplibre-gl-js/docs/) · [OpenFreeMap terms and attribution](https://openfreemap.org/) · [PMTiles extracts](https://docs.protomaps.com/basemaps/downloads) · [Protomaps on Cloudflare](https://docs.protomaps.com/deploy/cloudflare)

This checks the spatial join. It does not establish the absence of a city order. ### Oklahoma and Texas

- **Oklahoma Forestry Services.** The public map resolves to the v9 county layer. The count query returned 77. A full query for county name and status, without geometry, was just 5,777 bytes. Atoka and Choctaw returned `None`. The other codes are county ban, governor’s ban and ozone alert. OFS says resolutions received by 4 p.m. post the same day, later ones the next day. Its item warns of lag and asks users to verify locally. Its attached order, resolution 2026-512, was named for November 9–22. The scanned order said up to fourteen days, allowed extension by another decision, and excluded federal land. A later resolution was unverified. Show “Check the county order” in this case and suppress start/end alerts pending confirmation. - **Texas A&M Forest Service.** The downloadable TXT, read in full, used a UTF-16LE byte-order mark. Its November 23 header declared 82 bans at 10:52:12 a.m. Exactly 82 unique county names followed, starting with Archer, Armstrong and Atascosa. TFS updates as counties issue or lift orders. Its site policy invites personal, educational and other noncommercial use with attribution and retention of notices. An unrestricted commercial redistribution grant was not established. - **Reuse changes the API design.** Esri records usage constraints in `licenseInfo` and attribution in `accessInformation`. Several tested items, including FL, IA, IN, LA and ND, had blank item terms. Minnesota permits credited derivatives but restricts redistributing or displaying the entire dataset. New Jersey requires full metadata on redistribution, preservation of coordinate reference information and a prescribed credit/disclaimer. Keep links and normalized facts scoped to permitted use. Clear raw exports and commercial rights source by source. ### Search and agent access

Google recommends prerendered or server-rendered HTML for users and crawlers. It uses trustworthy sitemap `lastmod` values for material page changes and identifies near-identical location doorway pages as spam. That favors an indexable county page with evidence, dates and real restrictions. A ZIP lookup can link to that page. ## Not found

I found official pointers in all 50 states. I did not establish a nationwide feed that reconciles municipal, county, tribal, state and federal orders. Nor did I establish a fixed publication schedule or an open commercial API license for most local layers. An ArcGIS edit date is evidence of one edit, not a refresh commitment.

There is no production CPU benchmark or end-to-end email/push delivery result from this notes-only run. The budget, subscriber peak, source agreements and cutover date remain open. Those inputs decide the paid tier and rollout.

## Inferences and implementation choices

1. **Keep the answer on one screen.** Use a plain GET form for ZIP, one large result, the jurisdiction and activity covered, source/checked time and “Read the official order.” Keep “Pick on map” and “Alert me” secondary. Use words as well as color. “Yes — county debris-burning ban,” “No county ban reported,” “Restrictions apply” and “Check locally” cover cases that a red/green switch cannot. For a split ZIP such as 74008, show both counties and let the visitor pick or drop a pin. Preserve leading zeros. A PO-box-only or unmatched ZIP gets a county/map fallback.
2. **Choose Astro for the directory, keep the Worker small.** Astro’s templates and file routing earn their place once there are state directories and recurring county layouts. Leave `output: 'static'` as the default. Use the Cloudflare adapter with `prerender = false` only for live results, and a custom Worker entry for `scheduled` and `queue`. Plain HTML plus a vanilla Worker is equally credible for an OK/TX-only edition. Hono earns its dependency if shared validation and routing become cumbersome. The map can load its code and geometry after a click in any of these stacks.
3. **Decouple refresh from deployment.** Serve home, directory and documentation assets directly. Read D1 for county HTML and public JSON, using the same status function. Leave these paths out of the static build so an old asset cannot shadow the Worker route. Cache public results at the edge, initially for up to five minutes, bounded by the next start, expiry or source freshness deadline. Cache expiry must also change the answer when an order expires. Worker Cache API hits still invoke the Worker, and local cache deletion does not purge other regions. Keep precise-pin lookups and subscription responses out of shared caches. A daily full static rebuild is viable for a small directory if the freshness promise allows it. At sustained high read volume, generate changed county HTML/JSON into a separate public R2 bucket with CDN caching. Private evidence and subscriptions stay separate. [Cache API](https://developers.cloudflare.com/workers/runtime-apis/cache/) · [R2 CDN](https://developers.cloudflare.com/cache/interaction-cloudflare-products/r2/)
4. **Poll by publisher.** One UTC cron dispatches due sources to small jobs. For an initial pilot, try hourly OK/TX checks and time daily sources around their published update. Track publisher lag separately from delivery lag. Use ETags or Last-Modified where available, omit geometry on routine refresh, validate every page/code/count, and require Texas’s declared count to match unique recognized names. Stage a complete snapshot, then switch its version and insert transition events in a D1 transaction. A failed or overlapping run must preserve the last good version. Save `last_fetch_ok`, source update time, effective/end time and order URL separately. For event-driven feeds, an old edit date alone cannot prove staleness. Optional R2 archives permitted evidence by hash. Add KV only when useful. Fifty state keys rewritten hourly would cost 1,200 writes/day against Free’s 1,000. [ArcGIS pagination](https://developers.arcgis.com/rest/services-reference/enterprise/query-feature-service-layer/)
5. **Make “near me” explicit.** Let users watch a named county without sharing coordinates. For finer coverage, offer a selected spot and match new order polygons against it, with consent to retain the point. D1 can hold subscriptions, watched areas, source snapshots, transitions and a delivery outbox. Index by area and confirmation status. Store push endpoint, `p256dh` and `auth` privately, keep the stable VAPID private key in a Worker secret and pass only the public key to the client. Request permission after “Alert me.” Use real public subscriptions on the intended origin when Sam chooses it.
6. **Send once per meaningful change.** Seed the first snapshot silently. At signup, show any existing restriction immediately. Queue a start when an applicable order becomes effective or is first confirmed, using “newly reported” if its start is unknown. Identify each delivery by subscription, authority, order/episode and transition, with a uniqueness constraint and provider idempotency where supported. Recheck consent, status and expiry before retrying. Back off on 429/5xx, retire dead endpoints, suppress hard bounces and complaints, and keep failed work recoverable from D1. Push TTL must expire before the message becomes misleading. A provider’s acceptance does not prove delivery. A source outage or disappearing row cannot trigger a lift without the adapter’s documented withdrawal semantics.
7. **Choose email by peak day.** Start small with Resend Free, a verified sending domain, expiring double-opt-in links, rate-limited signup and immediate unsubscribe. Keep promotional content out of order alerts. A single ban with 250 email subscribers exceeds the free daily cap even before confirmations. If ingest already requires Workers Paid, Cloudflare Email Sending is economical once the account’s sending headroom is confirmed. Cloudflare publishes bounce/complaint events through Queues. [Email events](https://developers.cloudflare.com/changelog/post/2026-07-15-event-subscriptions/)
8. **Give Google and agents stable addresses.** Index state hubs and substantive county pages such as `/ok/tulsa-county/`. Put the current scoped answer, official source, effective dates and coverage gaps directly in HTML. Use ordinary links, canonical URLs and a sitemap updated when the status, order or coverage changes. Keep ZIP permutations, arbitrary map coordinates and thin unsupported pages out of the index. A new host can preserve old URLs. Preview separately and let Sam choose the domain cutover.
9. **Define the read API before adding features.** Proposed examples are `GET /api/v1/status?county_fips=40143`, `?zip=74008` and `?lat=36.154&lon=-95.9928`. A resolved lookup returns `active | none_reported | restricted | unknown`, an array of applicable orders with jurisdiction and activity, order/source URLs, publisher update, checked time, effective/expiry times, freshness and the scopes actually covered. Ambiguous ZIPs return candidates with an explicit `needs_location` flag. Unsupported coverage is explicit, a malformed coordinate is a 400, and a missing record never defaults to false. Publish `/openapi.json`, examples, coverage-by-source and an ETag. Default to keyless, rate-limited reads.
10. **Roll out by evidence.** Restore OK/TX first. Next test IN, LA and MS against issuing authorities, then add daily/area-specific sources such as MN and WI. Give other states a linked official directory immediately. Replay the McCurtain expiry conflict, a split ZIP, an incomplete feed, duplicate queue delivery and unsubscribe-before-retry. Measure Worker CPU for the largest feed and encrypted alert batches and test real iPhone Home Screen, desktop and email delivery before promising timing. Upgrade if measured CPU, dynamic requests or credible peak-day recipients exceed the free limits.
