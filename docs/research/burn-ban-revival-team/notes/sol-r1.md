# Is There a Burn Ban? Research notes
2026-11-23 · US first · data and implementation evidence

## Takeaway

Keep one screen and an official link. Use Astro on Cloudflare, with a ZIP resolver, an optional map, and alerts driven by verified status changes.
Start with county feeds, then expand by activity and jurisdiction. Use the 51-area inventory as a source directory while expanding automated coverage.
No nationwide legal-ban feed surfaced. Preserve scope and freshness so blanks, stale rows and land-only coverage never become a universal “Nope.”

## Inferences

- **Product.** Keep the home screen to a ZIP field and the answer, e.g. “Yes — Tulsa County has an outdoor burn ban” or “Nope — no county burn ban reported.” Show the named jurisdiction, exact activity/scope, effective time if supplied, when it was last verified, and an “Official order” link. Use “Restrictions apply” for partial/time- or activity-specific scope and “Can’t confirm” for missing, stale or ambiguous inputs. Only display a negative for a scope a fresh, complete feed explicitly covers. A map and alert action can sit below the result.
- **Scope and ingestion.** Launch county-level outdoor/debris bans first. Pilot TX/OK with FL/IN/IA/LA/MS next, plus AR after a reliable official route is verified. KY is a positive-only reported list unless stronger local coverage is obtained. Add MN, MI, WI and AK with permit or land-scope labels, then ND and WY with conditions and footprints. Add AZ, ID, MT, NM, NV, OR, UT and WA by land manager after validation. Missouri can enter that queue once its mixed-source feed and reporting completeness are validated. Encode confirmed recurring rules as scoped calendar facts, and publish a directory for the remaining locations. Treat campfire, residential debris, agricultural/prescribed burning and indoor wood smoke as different activities. Provide the nearest issuing authority per result, preferring the signed order and retaining the state map as fallback. For overlapping sources, show every applicable order and surface conflicts.
- **Feed integrity.** Per adapter store issuer, official link, coverage/scope and expected feature universe, authority positives/negatives, effective/start/end/rescission, source timestamp, observed fetch time and a normalized/raw checksum. Check schema, known labels, distinct FIPS counts, time zones and stale payloads. A list disappearing or a field going blank becomes unknown with retained last-known evidence. Poll a 30–60 minute pilot with per-source pacing, conditional requests and backoff. Collect two weeks of snapshots and manually compare real changes to orders before enabling “Nope” or alerts. Start with publication and observation thresholds per source, since an infrequently edited but still active order can be valid. Measure people and jurisdictions with confirmed answers by activity, not just state pages. Measure feed uptime, discrepancies and update delay.
- **ZIP and map.** Prebuild compact ZIP-to-FIPS shards from HUD, with Census fallback. Preserve leading zeros, version the county-equivalent geography, and return each candidate when a ZIP spans boundaries. Louisiana parishes, Alaska boroughs/census areas, Connecticut planning regions and Virginia independent cities need aligned vintages or explicit joins. Rank by HUD residential share as a convenience and invite county confirmation. Do not subscribe across all candidates unless explicitly selected. Use an optional map with generalized county boundaries first, state-by-state assets and lazy-loaded MapLibre or a simple county layer. Add point-in-polygon for city, land-manager and district restrictions. When precision changes the answer, ask for a pin or exact jurisdiction, and show the narrower rule alongside the county result. County and district overlays should remain legible with or without a basemap. Ship a keyboard-accessible county search alongside map navigation. [Census Connecticut geography change](https://www.govinfo.gov/content/pkg/FR-2022-06-06/pdf/2022-12063.pdf)
- **Astro architecture.** Use Astro for prerendered state/county pages and a small ZIP input script. Serve static assets directly on Cloudflare Workers. Generate stable, full HTML for authority links, known rules and scope. On verified high-coverage pages, let a cacheable Worker route render current status into the initial HTML from the published snapshot, including its freshness check. Use static HTML for directories and other durable pages. For pure SSG, show dated snapshots and refresh only the dynamic answer; avoid treating a build-time status as live. Keep polling independent of site deploys. Use Cron, D1 for current status and subscriptions, and immutable compact snapshots if volume warrants. Put the app on a preview hostname first; budget and the live-domain cutover can be decided separately. Preserve existing URLs where practical, and redirect exact replacements if paths change. [Google site move guidance](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes)
- **Alerts.** On explicit opt-in, let users select a county or a map point and activity. Confirm email, support unsubscribe and deletion, store only needed contact and jurisdiction fields, and use service worker Web Push with VAPID. Use a D1 outbox and optional Queue. Schedule verified future starts and distinguish late discovery from a ban that just took effect. Idempotency key includes subscriber, channel and stable order transition ID. Diff verified state and scope so a fetch outage, first import or wording change cannot create a new-ban blast. Allow confirmation for shaky sources, include issuer, official link and effective timestamp, and remove expired push subscriptions. Use provider quotas from its current docs, set burst and daily caps, and retain immediate alerts for verified transitions.
- **SEO and agents.** Keep canonical `/us/ok/tulsa-county/`-style pages and linked state indexes. A useful place page has official source, actual scope and exceptions, current status or honest coverage gap, last verified timestamp and a permanent URL. Index verified/useful pages in a sitemap and leave thin ZIP variants, unverified template permutations and map filters out. Use accurate `lastmod`, good internal links and Search Console. Publish `GET /api/v1/status?zip=74103` plus county FIPS and optional `lat/lon` queries. Responses include candidates if ambiguous, status (`active`, `restricted`, `no_reported_ban`, `unknown`), activity, geography, authority, source and official order URLs, source/checked timestamps effective bounds and advisory context when available. Use JSON, short cache TTL and ETag, versioned OpenAPI, and equivalent human pages. For documented batch use, offer a sized dated snapshot if underlying rights permit. Public MCP can wait until there is demand for more than the HTTP interface.
- **Beyond the US.** US directory and status quality come first. Manitoba is a bounded pilot if normalized rule semantics and upstream rights check out. Do not re-use ZIP or county assumptions in Canada.
