# Email deliverability for Is There a Burn Ban?

Reviewed November 24, 2026.

## Why the first message reached spam

A new sending domain has little history for Gmail to judge. A message can pass authentication and still land in spam while Gmail learns how recipients respond to the sender. Sender and shared IP reputation, complaint history, sending patterns, and the destinations in the email all matter. One message gives us too little evidence to identify the cause. Sam’s **Not spam** click was an appropriate response to a message he expected. Start with that message’s authentication results, then build a sending history with genuine opt-ins. [Google sender guidelines](https://support.google.com/mail/answer/81126) · [Cloudflare deliverability](https://developers.cloudflare.com/email-service/concepts/deliverability/) · [Postmark’s domain warm-up guide](https://postmarkapp.com/guides/how-to-warm-up-a-domain)

Postmaster Tools is worth verifying now for future diagnostics. It reports what Google sees for mail to personal Gmail accounts. At this volume, a verified dashboard can stay empty because Google withholds data on low-volume days. Use the original message and Cloudflare’s activity log for immediate troubleshooting. Cloudflare’s Delivered status means Gmail accepted the message over SMTP. Check the receiving mailbox for folder placement. [Google Postmaster setup](https://support.google.com/mail/answer/9981691) · [Postmaster dashboards](https://support.google.com/mail/answer/14668346) · [Cloudflare placement troubleshooting](https://developers.cloudflare.com/email-service/reference/troubleshooting/)

## In order

1. **Sam** — In desktop Gmail, open the original message and select **More → Show original**. Look for `SPF: PASS`, `DKIM: PASS`, and `DMARC: PASS`. For the Cloudflare send, expect SPF for `cf-bounce.isthereaburnban.com`, DKIM selector `cf-bounce` for the sending domain, and DMARC aligned with the visible From domain, `isthereaburnban.com`. If any check fails, compare `Authentication-Results` and `DKIM-Signature` with **Cloudflare → Compute → Email Service → Email Sending → select the domain → Settings** before changing the copy or policy. An aligned SPF or DKIM pass satisfies DMARC. Expect both on direct Cloudflare delivery. [Gmail Show original](https://support.google.com/mail/answer/29436) · [Cloudflare authentication](https://developers.cloudflare.com/email-service/concepts/email-authentication/) · [Cloudflare DNS verification](https://developers.cloudflare.com/email-service/configuration/domains/#verify-email-sending-records)
2. **Sam** — Sign in to [Google Postmaster Tools](https://postmaster.google.com/). Go to **Manage Domains → Add new domain**, enter `isthereaburnban.com`, and click **Create**. Go back to **Manage Domains → ⋮ → Verify domain** and copy the TXT value. In **Cloudflare → isthereaburnban.com → DNS → Records → Add record**, choose **TXT**, name **`@`**, TTL **Auto**, and paste the exact `google-site-verification=…` value Google displays. Save the separate record, then click **Verify** in Postmaster Tools. Google uses the SPF or DKIM identity for dashboard data. If the received message uses a distinct authenticated bounce subdomain and you want separate SPF-based metrics, add that domain in Postmaster and publish its own verification record at `cf-bounce`. [Google Postmaster setup](https://support.google.com/mail/answer/9981691)
3. **Sam** — Go to **Cloudflare → Compute → Email Service → Email Routing → select the domain → Routing Rules → Create routing rule**. Enter `dmarc`, select **Send to an email**, pick the verified mailbox that already receives `alerts@`, and save. Check that both rules are active. Then go to **DNS → Records**, edit the existing **TXT** named **`_dmarc`**, and save the single value **`v=DMARC1; p=reject; rua=mailto:dmarc@isthereaburnban.com;`** with TTL **Auto**. Keep `p=reject` once legitimate sends pass alignment. Review the XML aggregate reports for unexpected senders and authentication failures. A same-domain reporting address needs no external authorization. If you later point `rua` directly at a reporting vendor’s domain, the vendor must authorize that destination in DNS. [Cloudflare routing rules](https://developers.cloudflare.com/email-service/configuration/email-routing-addresses/) · [Cloudflare DMARC setup](https://developers.cloudflare.com/email-service/configuration/domains/#sending-records) · [RFC 9990, aggregate reporting](https://www.rfc-editor.org/rfc/rfc9990.html)
4. **Code at release** — The Worker uses `SITE_URL` for HTTPS county, confirmation, and unsubscribe links. The apex still serves the Vercel site. For a pre-cutover release, use the live preview Worker and prefer the branded `https://beta.isthereaburnban.com` once it serves the updated email endpoints. Switch to `https://isthereaburnban.com` when the Worker serves the apex and keep previously mailed action URLs working. The code supplies matching text and HTML and tags eligible subscriber messages with both unsubscribe headers. [Current Worker configuration](../wrangler.jsonc) · [Google sender guidelines](https://support.google.com/mail/answer/81126)
5. **Sam, after the release is live** — Request one confirmation from your own address, then use the operator delivery check with a confirmed subscriber on the test roster. In Gmail’s **Show original**, check all three authentication passes and that the subscriber message has both MIME parts and both list headers. Look for `list-unsubscribe` and `list-unsubscribe-post` in the aligned `DKIM-Signature` header’s `h=` list. Check the same raw fields if Resend is used. Open the footer link and finish unsubscribing a disposable test subscription. If Gmail shows **Unsubscribe** next to the sender, use that on another test subscription. Gmail controls when its button appears. [Google one-click unsubscribe FAQ](https://support.google.com/mail/answer/14229414) · [RFC 8058](https://www.rfc-editor.org/rfc/rfc8058.html)
6. **Sam, ongoing** — Keep the From name and address consistent as `Is There a Burn Ban? <alerts@isthereaburnban.com>`. Start with the alerts people actually requested and let volume grow with real confirmed subscriptions and real county events. Keep `alerts@` monitored and process mailto requests promptly. Review Cloudflare’s **Email Sending → Activity log** for bounces and complaints and check Postmaster when data starts appearing. Google recommends staying below 0.1% user-reported spam and avoiding 0.3% or higher. Yahoo requires below 0.3% and asks bulk senders to honor opt-outs within two days. Retire hard-bounced addresses and use the provider’s suppression list. ## Headers and unsubscribe

- Gmail requires all senders to use SPF or DKIM and meet its infrastructure and message-format rules. For domains sending around 5,000 or more messages per day to personal Gmail accounts, Google adds SPF **and** DKIM, DMARC, alignment, and one-click unsubscribe for marketing and subscribed messages. Yahoo also requires bulk senders to provide easy opt-outs, with RFC 8058 preferred. Implement it for recurring county alerts now. Confirmation, operational mail, and delivery checks addressed directly to a sandbox mailbox are one-off messages. A test sent to an enrolled subscriber includes that subscriber’s unsubscribe controls. [Google sender guidelines](https://support.google.com/mail/answer/81126) · [Google bulk-sender FAQ](https://support.google.com/mail/answer/14229414) · [Yahoo sender requirements](https://senders.yahooinc.com/best-practices/)
- The Worker sends `List-Unsubscribe` with the direct HTTPS URL first and a `mailto:alerts@isthereaburnban.com` fallback second. The HTTPS endpoint accepts `List-Unsubscribe=One-Click` in a form POST. Either standard form encoding works. A successful machine request returns an empty 204 without a redirect and disables only the linked county selection. Repeating it preserves the original opt-out time. A browser GET opens a form, so link previews leave the subscription alone. The browser’s submit button uses the same opt-out. The outbox rechecks subscription eligibility before provider handoff. [RFC 8058](https://www.rfc-editor.org/rfc/rfc8058.html) · [RFC 2369](https://www.rfc-editor.org/rfc/rfc2369.html)
- The mailto request is handled by Sam. Its prefilled subject contains `Unsubscribe` followed by the subscription token. For a valid request, open `https://<email-link-host>/api/v1/email/unsubscribe?token=<token>` privately and click **Unsubscribe**. Use the host serving the Worker for that subscription. Handle requests within two days and keep the token private. If the email lacks a token, ask the sender to use the footer link from the alert they want to stop. [Yahoo unsubscribe requirements](https://senders.yahooinc.com/best-practices/)
- With Cloudflare’s Workers API, pass `text`, `html`, and the allowed list headers. Cloudflare generates the MIME and transport fields, controls `Date`, `Message-ID`, `Return-Path`, and `DKIM-Signature`, and documents DKIM signing for one-click unsubscribe. Pass `From`, `To`, `Subject`, and any `Reply-To` through their named API fields. An unallowlisted, non-`X-` custom header rejects the whole send. Resend also accepts the message parts and custom list headers. [Cloudflare Workers API](https://developers.cloudflare.com/email-service/api/send-emails/workers-api/) · [Cloudflare header allowlist](https://developers.cloudflare.com/email-service/reference/headers/) · [Resend Send Email API](https://resend.com/docs/api-reference/emails/send-email) · [RFC 8058](https://www.rfc-editor.org/rfc/rfc8058.html)
- Gmail’s `Feedback-ID` helps high-volume senders identify which streams generate complaints in Postmaster Tools. Google expects a stable sender ID of 5–15 characters, optional shared identifiers such as message type, and DKIM signing after inserting the header. For example, `Feedback-ID: alerts:itabb01` uses an alert-stream identifier and one stable sender ID. Avoid recipient IDs and individual message identifiers. Cloudflare’s current Workers allowlist omits `Feedback-ID`. Its managed `CFBL-Feedback-ID` serves a different protocol. Revisit the Gmail header when volume justifies it and the sending transport can support it. [Gmail Feedback Loop](https://support.google.com/mail/answer/6254652) · [Cloudflare header allowlist](https://developers.cloudflare.com/email-service/reference/headers/)

## Copy checklist

| Do | Avoid |
| --- | --- |
| Name the county and the change in a short, sentence-case subject. Lead with the action or status. | Fake reply prefixes, vague `Test:` subjects, shouting, excessive punctuation, and promotional urgency. |
| Use the same words in plain text and minimal HTML. Use short paragraphs, headings, and descriptive action labels. Pair any body emoji with words that carry the status. | Image-only copy, remote assets, hidden filler, and icons that replace a status word. |
| Give each notice a direct, readable HTTPS link on the site. Keep the county page, official sources, and unsubscribe easy to find. | Masked destinations, URL shorteners, redirect hops for tracking, and tracking pixels. Check links before release. |
| Identify the sender and why the reader got the message. Use confirmed opt-in, consistent sender identity, and an easy opt-out. | Bought or imported addresses without consent, mass warm-up sends, and repeated mail to hard bounces. |

[Google message-format guidelines](https://support.google.com/mail/answer/81126) · [Cloudflare content and link guidance](https://developers.cloudflare.com/email-service/concepts/deliverability/) · [Mailchimp content guidance](https://mailchimp.com/resources/email-content-for-deliverability/) · [M3AAWG sender practices](https://www.m3aawg.org/sites/default/files/doc_files/M3AAWG_Senders_BCP_Ver3-2015-02.pdf)

Keep subject lines text-only for these alerts. Nielsen Norman Group’s studies found more negative reactions and no meaningful increase in opening intent. A practitioner’s campaign test also reported more complaints in its emoji sends. These studies measured reader behavior. Gmail’s published rules focus on message format, authentication, and recipient feedback. For a future subject-line trial, put one relevant emoji at the end of a complete subject, verify the wording on mobile and with assistive tech, and compare complaints as well as engagement on a consenting sample. The Worker pairs occasional decorative body icons with written status.
